# 2019 Primary (Aug 6, 2019) — county crosstab vs. precinct-file discrepancies

Comparison of the county-level primary CSVs in this directory

* `20190806__ms__democratic__primary__county.csv`
* `20190806__ms__republican__primary__county.csv`

(parsed from the Secretary of State's certified crosstab PDFs) against the
precinct-level CSVs in `2019/counties/` (`20190806__ms__primary__<county>__precinct.csv`,
which come from separate county-level sources). Generated by
`crosscheck_2019_primary.py` at the repo root.

## Summary

* **2,627 of 2,780 comparable (county, office, candidate) values match exactly.**
  153 differ (58 DEM, 95 REP).
* Assessment of the 153 differences:
  * **61** — the county's precinct file is missing
    whole precincts (every candidate in that county reads low). Concentrated in
    a handful of counties: DEM Attala (1), DEM Grenada (1), DEM Holmes (4), DEM Madison (2), DEM Marshall (1), DEM Pontotoc (1), DEM Sunflower (1), REP Attala (19), REP Hancock (1), REP Jefferson (14), REP Jones (1), REP Marion (1), REP Marshall (1), REP Oktibbeha (2), REP Rankin (11), REP Winston (2).
  * **81** — one cell differs by a small amount
    (usually ±1–50). Neither source is self-evidently wrong; the certified
    crosstab value is kept.
  * **2** — Rankin REP statewide candidates whose
    gap traces to the county's precinct file having been built from a scan
    that is missing a page (see §6).
  * **5** — the printed crosstab cell is
    demonstrably wrong (verified on rendered page images); the precinct data
    appears correct. (One more cell — Mussiett's HD 87 Lamar value, grouped
    with the printed-TOTAL errors in §2 — also falls in this category.)
  * **1** — the precinct file's value is implausible
    while the crosstab is internally consistent.
  * **2** — digit transpositions; both sources are
    plausible, the crosstab value is kept.
* The crosstabs' own TOTAL columns reconcile with their county cells for all
  182 DEM candidates and all but 5 REP candidates — i.e., where the crosstab
  has a typo'd cell, its TOTAL is consistently wrong too, so internal
  reconciliation alone cannot catch these. The precinct comparison can.

### Correction to the Republican county CSV (Lieutenant Governor)

The first parse of the Republican crosstab PDF missed the Lieutenant
Governor race entirely: the PDF prints that section's header as
"**Lt. Governor**", which the parser's office-header matcher didn't
recognize, so Delbert Hosemann's and Shane Quick's rows (164 rows, 2 per
county) were filed under Governor. The parser now recognizes the
abbreviated header and the Republican county CSV was regenerated — the
vote values are unchanged (they always were the Lt. Governor section's
values); only the office labels changed. The Democratic PDF spells the
header out in full, so the Democratic file was never affected. This fix is
what brought the Republican Lieutenant Governor rows into the comparison
above (+11 mismatches, none of them caused by the relabeling).

## What could not be compared

* **7 counties have no primary precinct file** (Benton, Bolivar, Franklin,
  Scott, Sharkey, Simpson, Smith): 336 county-CSV rows had nothing to compare.
* **District Attorney, Public Service Commissioner and Transportation
  Commissioner races are absent from the precinct files** entirely: 774
  county-CSV rows had nothing to compare. (These races' only verification is
  the crosstab's TOTAL column, which reconciles.)
* The remaining ~55 uncompared rows are minor-party/uncontested cells in
  counties where the precinct file omits that race (485 DEM + 680 REP rows
  had no precinct counterpart in total).

### 6. Rankin Republican statewide races — resolved: the precinct file was built from an incomplete scan

The 11 REP Rankin rows in §4 (Governor ×3, Lieutenant Governor ×2, Secretary
of State ×2, Attorney General ×3, State Auditor ×1) all trace to one root
cause, established by OCR-extracting the county's own scanned recapitulation
(`Rankin Primary REP.pdf` in the 2019 sources — a 42-page image scan with no
text layer) with `extract_2019_rankin_rep_precinct.py` at the repo root:

* **The certified crosstab values are correct.** The county recap's own
  printed TOTAL column matches the statewide crosstab's Rankin values
  exactly for every one of the 14 races it covers (e.g. Watson 16,151,
  White 27,101, Reeves 12,510, Waller 13,503, Hosemann 26,898).
* **The precinct file was built from this same scan, which is missing a
  page.** The recap lays each group of offices out as candidate rows ×
  precinct columns, with the ~48 precincts cycled across 4–5 pages per
  group. The *first* office group (the five statewide races above) has only
  4 pages: the scan jumps from the blank page 2 straight to the page whose
  first column is Crossroads. The Antioch-Mayton → Crest Park column page
  for that group was never scanned. Every later group (State Treasurer
  onward) has a complete 5-page cycle including those precincts.
* **The existing precinct file mirrors the scan exactly**: its values for
  the 37 precincts the scan does show match the OCR digit-for-digit, and the
  11 missing-page precincts (Antioch-Mayton, Brandon Central, Brandon City
  Hall, Briar Hill, Castlewoods East, Castlewoods West, Cato, City Hall,
  Clear Branch, Cleary, Crest Park) are present as rows with *empty* vote
  cells for exactly those 11 candidates. Its sums therefore fall short of
  the crosstab by precisely the missing page's votes.
* **The gap cannot be closed from this source.** The missing page does not
  exist anywhere in the PDF (page 2 is blank bleed-through), so the 11
  precincts' votes for those 11 candidates are unrecoverable without a
  complete copy of Rankin County's Republican recapitulation. The crosstab's
  county-level values stand; the precinct file remains incomplete for those
  cells, and the empty cells are retained rather than guessed at.

Raw OCR output is cached at `cache/2019-rankin-rep/` (not committed).

## Reproducing

```
uv run python extract_2019_primary_county_pdf.py \
    "<SoS DEM pdf>" 2019/20190806__ms__democratic__primary__county.csv --party DEM
uv run python extract_2019_primary_county_pdf.py \
    "<SoS REP pdf>" 2019/20190806__ms__republican__primary__county.csv --party REP
uv run python crosscheck_2019_primary.py 2019/20190806__ms__democratic__primary__county.csv \
    2019/20190806__ms__republican__primary__county.csv

# Rankin REP scan OCR (§6; ~39 vision-model calls, cached per page):
uv run python extract_2019_rankin_rep_precinct.py --workers 6
```
